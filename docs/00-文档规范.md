# 文档规范

> 编号：规范 00  
> 状态：现行  
> 更新：2026-10-16  
> 说明：本仓库所有项目文档的命名、分类、元数据和正文格式规则。新增或修改文档前先读本文件。

## 1. 目录与分类

文档按用途分类，每类一个目录，目录名为 `两位编号-中文类名`：

| 目录 | 用途 | 放什么 |
|---|---|---|
| `01-设计/` | 游戏要做成什么样 | 游戏方向（唯一规格）、版本范围 |
| `02-设定/` | 世界观与美术资产 | 世界观设定、美术参考、资产清单 |
| `03-计划/` | 什么时候做、按什么顺序做 | 迭代计划、里程碑 |
| `04-审计/` | 对照检查与执行记录 | 试玩复核、数值校准、审查结论；复核引用的测试截图放 `截图/迭代N/` |
| `05-原始输入/` | 外部交来的原始材料 | 策划案原文、参考图；原样保存，不改内容、不改文件名 |

本文件 `00-文档规范.md` 放在 `docs/` 根目录，不属于任何分类。

`05-原始输入/` 只做存档，不适用 §2–§5 的命名与格式规则，也不登记索引；其内容被整理进其它文档后，以整理后的文档为准。

新增分类时顺延编号，在本表登记即可，`tests/unit/docs.test.mjs` 从本表读取分类。不要把文档直接放在 `docs/` 根目录。

## 2. 文件命名

- 格式：`两位编号-中文名称.md`，例如 `01-游戏方向.md`。
- 编号在**各分类目录内**独立计数，从 `01` 开始连续递增；已发布的编号不重排、不复用。
- 文档废弃时不删除编号，把状态改为“历史参考”或“已废弃”。
- 名称使用中文名词短语，不超过 14 个字；不加日期、版本号、“最终”“新版”等修饰词；不使用空格和英文大写缩写（必要的专有名词如 `UI` 除外）。

## 3. 文档头

每份文档第一行是一级标题，与文件名中的中文名称一致；空一行后紧接一段引用块元数据，四项缺一不可：

```markdown
# 游戏方向

> 编号：设计 01-01  
> 状态：现行  
> 更新：2026-01-01  
> 说明：一句话说明本文件的用途和适用范围。
```

- **编号**：`分类名 分类编号-文件编号`，如 `审计 04-01`；本文件为 `规范 00`。
- **状态**：只能取以下值：
  - `草稿`：内容未定，不作为开发依据；
  - `执行中`：计划或记录类文档正在推进；
  - `现行`：当前有效，开发以此为准；
  - `已完成`：一次性报告或记录，已结束；
  - `历史参考`：被其它文档取代，仅供追溯，必须在说明里写明被谁取代；
  - `已废弃`：内容作废，保留只为不打断编号。
- **更新**：最后一次实质修改的日期，格式 `YYYY-MM-DD`。
- **说明**：一句话；若与其它文档有优先级关系，在这里写清楚。

元数据行末尾保留两个空格以强制换行（最后一行除外）。

## 4. 正文结构

- 一级标题只用于文档名，全文只出现一次。
- 二级标题统一编号且连续：`## 1. 标题`、`## 2. 标题`。
- 三级标题跟随所属二级编号：`### 1.1 标题`、`### 1.2 标题`。
- 不使用四级及以下标题；需要更细分时改用加粗段落或列表。
- 文档头与第一个二级标题之间可以有一段导语，导语里不使用标题。

## 5. 正文写法

- 中文正文，同一文档内中英文、数字之间的空格风格保持一致。
- 先结论后细节；一个段落只讲一件事。
- 数值、规则、阈值用表格，不在段落里散写。
- 代码、文件路径、命令用反引号：`npm test`、`src/data/tuning.js`。
- 引用本仓库其它文档时写书名号加相对链接：`[《游戏方向》](../01-设计/01-游戏方向.md)`；引用章节写 `§4`。
- 引用代码时写相对仓库根的路径；不写绝对路径。
- 可勾选项用 `- [ ]`。

## 6. 唯一基准与冲突处理

- `01-设计/01-游戏方向.md` 是玩法、数值、美术、工程和界面的唯一基准。
- 其它文档（包括 `05-原始输入/` 中的原稿）与它冲突时，以它为准，并把冲突文档改为“历史参考”或在其中注明。
- 修改玩法数值的顺序：先改《游戏方向》§4，再改 `src/data/tuning.js`，最后跑 `npm test`（测试校验二者一致）。

## 7. 新增文档流程

1. 判断用途，放进对应分类目录；没有合适分类时先在 §1 登记新分类。
2. 取该目录下最大编号加一作为文件编号。
3. 按 §3 写文档头，按 §4 写标题结构。
4. 如果它取代了旧文档，同时把旧文档状态改为“历史参考”并在说明中指向新文档。
5. 在 §8 的索引表中登记；`npm test` 会校验文档头、标题层级与索引。
